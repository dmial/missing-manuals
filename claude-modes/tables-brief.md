## Таблица 3: Доставка оснастки

Вопрос читателя: «мне нужно раздать X (скиллы / плагины / MCP) носителю Y (себе / команде / организации) — каким каналом?»

- **Строки**: носитель практики — соло / команда (pull) / организация (push).
- **Столбцы**: тип оснастки — скиллы · плагины · MCP-серверы и коннекторы.
- **Клетки**: канал доставки для пары, с оговоркой про Code (у него свои каналы).

Ключевые факты (все — в справочнике, раздел «Скиллы — каналы доставки», + проверено по support.claude.com в сессии):

- Скиллы: Settings → Skills — аккаунтный слой, claude.ai и десктоп — два окна к одному списку; ZIP-ом свои. Локальный Code аккаунтный слой НЕ читает (сноска 1), облачный Code подгружает автоматически. Файлы `.claude/skills` (личные/проектные) читает только Code; проектные приезжают с клоном.
- Плагины: каталог в приложении + «Add marketplace» (git-репо по URL); из директории — на аккаунт, самодобавленные — локально на устройстве. Скиллы плагинов работают в Chat и Cowork; хуки и суб-агенты — только Cowork. Code каталог не читает: CLI-маркетплейсы, включение `enabledPlugins` в `~/.claude/settings.json` (не переносится) или проектном `.claude/settings.json` (приезжает с клоном). Организация: внутренний маркетплейс (ZIP-загрузка или приватный GitHub-синк; публичные репо запрещены), режимы раздачи: installed by default / available for install / not available / required.
- MCP и коннекторы: удалённые коннекторы claude.ai — аккаунтный слой (Chat, Cowork; Code подхватывает при логине локально, выбором при старте облачной сессии). Локальные MCP: конфиг десктоп-приложения (Cowork) vs `.mcp.json` (Code) — раздельные. Организация: коннекторы на организацию; для Code — managed settings.

## Таблица 4: Контуры безопасности

Вопрос читателя: «какой контент можно скармливать и что агент в худшем случае сломает/сольёт?»

- **Строки**: пять исполнительных контуров (не три режима!): Chat (веб-бэкенд claude.ai) · Cowork локальный (VM) · Cowork облачный (контейнер) · Code локальный (прямое окружение) · Code облачный (VM).
- **Столбцы** (рабочий вариант, уточнить по материалу): изоляция и стенки · доступ к файлам · сеть · секреты и креды · худший ущерб.
- Под таблицей — выводы-эвристики: недоверенный контент — только контурам со стенками; секрет, попавший в среду, считается скомпрометированным (отсюда кредо-прокси); автономность куплена containment'ом (цепочка из справочника: containment → автономность).

Ключевые факты в справочнике: разрез «Среда» (песочница vs прямое окружение, сноски 3–4: контейнер/VM/прямое окружение), раздел «Зачем песочница — и почему в Cowork она несъёмная», git-контуры (кредо-прокси, суррогат `GH_TOKEN`, device flow заблокирован в облаке, единственный контур с настоящим токеном в среде — локальный Cowork), мост подключённой папки (VM без сети: файлы без сети / сеть без файлов), сноска 6 (мост `window.cowork` — паттерн брокера).

## Решения прошлой сессии (не пересматривать без пользователя)

- Принцип двух осей: **где корпус** (окошко/папка/репозиторий) → режим; **кто носитель практики** (я/команда/организация) → канал доставки оснастки. Оси независимы.
- Сила режима констант по строкам матрицы — чипы живут в заголовках колонок карты внедрения и в главе «Выбор режима».
- Эвристика: «Окошко → Chat. Папка → Cowork. Репозиторий → Code» + исключение исполнительского профиля (недоверенный контент → Cowork-песочница; полный доступ к машине → локальный Code).
- «Слепок знаний в скиллах плагина» в главах НЕ упоминать — пользователь счёл несущественным.
- Мысль «вертикаль (соло/команда/организация) не влияет на выбор режима, а выбирает канал доставки оснастки» с страницы «Выбор режима» удалена намеренно — её место на будущей странице «Доставка оснастки» (вводка). Страница «Выбор режима» — только заголовок и таблица, без вводок.

## Процесс

1. Черновик клеток пишет главная сессия (после чтения глав 1–3 серии целиком).
2. Адверсариальная валидация субагентами (Workflow): каждый агент читает `claude-modes-table.html` и целевую страницу, пытается опровергнуть каждое утверждение; факты вне справочника — сверять с support.claude.com / code.claude.com/docs; вердикты ok/fixed + источник.
3. Применить правки, механически сверить метки статусов, проверить рендер в браузере (включая обрезание всплывашек/карточек краями таблиц — ловили на `overflow: hidden`).
4. Стиль: плотный справочник, кавычки-«ёлочки», em dash, без англицизмов в роли несущих слов; термины точные (мост, device flow, PAT, кредо-прокси).
5. Коммиты — только по явной просьбе пользователя.
