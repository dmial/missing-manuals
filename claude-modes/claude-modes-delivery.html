Доставка оснастки: скиллы · плагины · MCP

Вертикальный разрез: каким каналом оснастка доедет до себя, команды и организации

Канал доставки выбирает носитель практики, а не режим: себе оснастку — скиллы, плагины, MCP-серверы и коннекторы — включаешь своими настройками; команде раздаёшь pull-каналами — каждый подключает сам; организация пушит админкой. Вторая ось — где живёт корпус знаний — выбирает режим и на канал не влияет: это глава «Выбор режима». Одна поправка сквозная: у Code свои каналы — файлы, CLI и собственный UI Code-таба десктопа вместо каталогов чат-приложения, поэтому он оговорён в каждой клетке отдельно.

Себе → свои настройки. Команде → pull: маркетплейс и клон — скиллам Team/Enterprise добавляет штатный шаринг. Организации → push: админка.

1 · Соловключаешь себе: свои настройки, свои файлы
Customize → Skills — аккаунтный слой

Встроенные включаешь галочкой, свои грузишь ZIP-ом. Слой живёт на аккаунте: claude.ai и десктоп — два окна к одному списку; Chat и Cowork читают его одинаково.

CodeЛокальный Code аккаунтный слой не читает — скиллы кладутся файлами: ~/.claude/skills (личные, на все проекты) или .claude/skills проекта. Облачная сессия Code, наоборот, подгружает скиллы аккаунта автоматически.
Каталог в приложении: Settings → Plugins

Из директории claude.ai плагин ставится на аккаунт. Свой каталог добавляется кнопкой «Add marketplace» — git-репозиторий по URL; самодобавленные каталоги хранятся локально на устройстве.

CodeКаталог приложения Code не читает: маркетплейсы — команда /plugin в CLI, включение — enabledPlugins в личном ~/.claude/settings.json (на другую машину и в облако не переносится).
Settings → Connectors — двумя ярусами

Удалённые коннекторы (OAuth) — аккаунтный слой: Chat и Cowork видят их сразу. Локальные серверы прописываются в конфиге десктоп-приложения — их видят десктопный Chat и Cowork.

CodeУдалённые коннекторы аккаунта Code подхватывает сам: локально — при логине, в облачной сессии — выбором при старте. Локальные серверы — своими каналами: .mcp.json проекта или claude mcp add (личный ~/.claude.json). Конфиг десктопа читает только Code-таб десктоп-приложения в локальных сессиях; терминальный CLI — нет, но импортирует его серверы командой claude mcp add-from-claude-desktop.
2 · Команда (pull)делишься: каждый подключает сам — каталог по URL, клон репозитория
Штатный шаринг (Team/Enterprise) — или плагин, или файлы в репо

На Team/Enterprise скилл шарится штатно: конкретным коллегам или всей организации (тумблеры Skill sharing и Share with organization; у получателя — разделы Shared и Organization skills в Customize → Skills, включает тумблером). На Free/Pro/Max шаринга нет — остаются плагин из общего маркетплейса (клетка справа) и пересылка ZIP-ом: ручная раздача без канала обновлений.

CodeПроектные .claude/skills в репозитории: приезжают с клоном каждому, включая облачные сессии. В общей синк-папке их прочитает только Code — подхват из подключённой папки Cowork не документирован.
Внутренний маркетплейс: git-репозиторий с каталогом

Команда держит каталог плагинов в git-репозитории; каждый добавляет его URL у себя сам («Add marketplace») — pull в чистом виде. Скиллы плагина доедут до Chat и Cowork; хуки и суб-агенты — только до Cowork.

CodeТот же репозиторий-каталог объявляется в проектном .claude/settings.json: каталог — ключом extraKnownMarketplaces, включение конкретных плагинов — enabledPlugins; оба приезжают с клоном, включая облачные сессии. Личный ~/.claude/settings.json остаётся на машине.
Каждый подключает сам — или коннектор приносит плагин

Удалённый коннектор — личное OAuth-подключение: раздать само подключение нельзя. Каналы команды — инструкция «подключи вот это» или командный плагин с коннектором внутри: тогда коннектор приезжает вместе с плагином.

Code.mcp.json в корне репозитория: версионируется, общий для команды, приезжает с клоном — и локально, и в облачные сессии.
3 · Организация (push)раздаёшь админкой: работает без действий получателя, закреплено политиками
Organization settings → Skills — прямой админ-канал (Team/Enterprise)

Владелец загружает скилл ZIP-ом — он появляется у всех участников в Customize → Skills включённым по умолчанию: push без действий сотрудника. Второй канал — плагины внутреннего маркетплейса («installed by default» / «required»), нужный в том числе для раздачи по группам.

CodeТретий уровень файлов скиллов — enterprise: раскладывается на машины средствами организации (managed-развёртывание, MDM).
Внутренний маркетплейс организации (Team/Enterprise)

Админ загружает каталог ZIP-ом или синкает из приватного GitHub-репозитория (публичные запрещены) и назначает каждому плагину режим раздачи: installed by default · available for install · not available · required.

CodeКаталог организации Code не читает — для него остаются CLI-каналы команды; принудительная раздача — управляемыми настройками (managed settings).
Коннекторы включаются на организацию

Админ добавляет удалённый коннектор в админке — он появляется у всех участников организации; OAuth-авторизацию каждый проходит под своим аккаунтом.

CodeДля Code — управляемый файл managed-mcp.json, разложенный на устройства MDM/GPO: раздаёт фиксированный набор серверов и берёт эксклюзивный контроль — коннекторы claude.ai подавляются, пока в managed settings не включён allowAllClaudeAiMcps. Сами managed settings — только allow/deny-фильтр серверов, не канал раздачи.

Три вещи, которые надо держать в голове

Code стоит особняком

Терминальный Code не читает ни аккаунтный слой скиллов, ни каталог плагинов, ни конфиг десктопа: его каналы — файлы (.claude/, .mcp.json) и CLI. Code-таб десктоп-приложения — исключение по MCP: локальные сессии подхватывают серверы из claude_desktop_config.json, плюс свой UI коннекторов и плагинов. Облачный Code — гибрид: аккаунтные скиллы и коннекторы подгружает, проектные файлы приезжают с клоном, личные (~/.claude/…) остаются на машине.

Плагин — контейнер доставки

Единица раздачи для команды и организации: внутри скиллы, коннекторы, хуки, суб-агенты. До Chat доезжают скиллы и коннекторы; хуки и суб-агенты — только до Cowork. Плагины собственной системы Code (CLI-маркетплейсы) несут полный набор — включая команды и суб-агентов.

Скилл из сессии умирает с ней

Скилл, созданный агентом по ходу работы, — просто папка со SKILL.md. Чтобы пережить сессию, он должен попасть в канал: ZIP-ом в Customize → Skills, файлом в .claude/skills, плагином в маркетплейс.
