Контуры безопасности: пять сред исполнения

Какой контент можно скармливать агенту — и что он в худшем случае сломает или сольёт

Режимов три, а контуров безопасности пять: у Cowork и Code локальный и облачный варианты — разные среды, от прямого окружения без стенок до VM у Anthropic, поэтому вопросы «что можно скармливать» и «что агент в худшем случае сломает» решаются на уровне контура, а не режима. Опасность, от которой строятся стенки, — prompt-инъекция: текст в чужом документе, который агент принимает за инструкцию («забудь правила, сделай X»); нести её может любое письмо, PDF или веб-страница. Таблица показывает, что каждый контур видит из твоего — файлы, сеть, креды — и что достаётся инъекции, если агент уговорён.

Сквозная оговорка: стенки режут только файловый риск. Риск коннекторов — действий во внешних сервисах от твоего имени — от стенок контура не зависит и режется отдельно: выбором подключений и подтверждениями действий.

Недоверенный контент → только за стенки. Секреты → как можно дальше от среды. Автономность → только там, где ущерб ограничен заранее.

Chatвеб-бэкенд claude.ai · только облако

Рабочей среды нет: диалог крутится в веб-бэкенде claude.ai, инструменты — вызовы сервисов (server tools). Под действие — выполнить код, собрать файл — бэкенд заказывает контейнер как услугу; тот эпизодичен: ~5 минут простоя — заморозка, предел 30 дней (цифры из API-документации этого же механизма). Исключение: локальные MCP-серверы исполняет десктоп-приложение на твоей машине.

Диска не видит: только вложения, загруженные в чат; результаты — файлами в чат. Локальный MCP-сервер, прописанный в десктопе, может открыть файлы — но исполняет его приложение, и это твой явный выбор, а не свойство среды.

Веб — server tools: поиск и загрузка страниц уходят с серверов Anthropic. Твоих кук у них нет, интранет и localhost недосягаемы.

В среде ничего твоего: OAuth-токены коннекторов держит инфраструктура Anthropic — вызовы идут от твоего имени, но ключей агент не видит.

Содержимое диалога и подключённые сервисы: инъекция может дёргать коннекторы от твоего имени — читать почту, писать в CRM, слить прочитанное. Машина и файлы вне чата недосягаемы — пока ты сам не прописал в десктопе локальные MCP-серверы: через них инъекции достаётся то, что эти серверы открывают (файлы, браузер).
Cowork · локальноцикл на машине, код в VM

Две среды на твоей машине: агентный цикл — нативно на устройстве, исполнение кода — в VM под гипервизором платформы (Apple Virtualization.framework, Hyper-V). Стенки вокруг кода, а не вокруг всего агента.

Подключённые папки — напрямую, запись сразу на диск, без стадии «применить». Остальная машина за стенками: keychain и ~/.ssh в VM не пробрасываются.

Двумя путями: веб-запросы агентного цикла (web fetch) идут нативно с устройства под контролем разрешений приложения; код и шелл ходят из VM по её сетевому allowlist'у. Наблюдение: из VM работает OAuth Device Flow — login-эндпоинты GitHub доступны; видимо, allowlist включает github.com целиком.

Keychain и SSH-ключи невидимы — но это единственный песочничный контур, где настоящий токен добывается прямо изнутри среды: device flow выдаёт gho_…-токен с широким scope repo (все приватные репо аккаунта); в облачных песочницах добыча заблокирована — токен можно только принести. Принесённый PAT живёт в среде как есть. Облако защищено брокером, этот контур — только сетевым списком.

Подключённые папки целиком — запись идёт сразу на диск; плюс токен, если он в среде: scope repo — это все приватные репозитории аккаунта. Кейчейн, куки и остальные файлы за стенками.
Cowork · облакоконтейнер у Anthropic

Обе среды у Anthropic: контейнер на сессию, уничтожается вместе с ней. Стенки контейнера тоньше VM (общее ядро Linux), но от твоей машины контур отделён самой удалённостью.

Твой диск — только через мост десктоп-приложения: файл копируется в облако разовым снимком, результат записывается обратно; работает, пока приложение онлайн. Удалять мост не умеет (rm → Operation not permitted).

Из контейнера — по allowlist'у; эндпоинты выдачи токенов не форвардятся — device flow из облака невозможен даже с твоего согласия. Мостовая VM на Mac вовсе без сети (CONNECT → 403): у облака сеть без файлов, у VM файлы без сети.

Кредо-прокси: настоящие ключи у брокера, в песочницу не попадают никогда; в окружении суррогат GH_TOKEN, который прокси подменяет только для прикреплённых репозиториев — а прикрепления у Cowork нет, суррогат мёртв (403). Работает только принесённый готовый PAT — прокси форвардит его как есть.

То, что сам занёс: скопированные в сессию файлы и принесённый PAT; плюс подключённая папка через мост, пока приложение онлайн (удалить файлы мост не может). Машина и её секреты недосягаемы.
Code · локальнопрямое окружение машины

Прямое окружение машины — твои тулы, env, dev-сервер. Стенок нет по умолчанию (встроенная песочница Bash — /sandbox — существует, но выключена, пока не включишь); страховка — пошаговые подтверждения команд.

Вся машина в пределах прав твоего пользователя: рабочая папка напрямую, остальное открыто шеллу.

Твоя сеть целиком: интранет, localhost, страницы за твоей авторизацией — curl ходит от твоего имени, как ты из терминала.

Все креды как есть: SSH-ключи из ~/.ssh, HTTPS-креды из keychain, переменные окружения, токены на диске. Git работает «сам собой» ровно поэтому.

Максимальный из пяти: одна отравленная PDF — и свободный шелл дотягивается до всей машины: кейчейн, куки, SSH-ключи, все файлы. Единственный контур, где ущерб ограничивают не стенки, а твой палец на подтверждениях.
Code · облакоVM у Anthropic

VM на серверах Anthropic: собственное ядро, стенки толще контейнера — внутри доступен даже Docker; своя на сессию, умирает с ней.

Только клон репозитория, прикреплённого к сессии; твой локальный диск недоступен. Наружу один путь — git push: ветка, PR.

По умолчанию — по allowlist'у (уровень Trusted: пакетные реестры, GitHub, cloud SDK); владелец окружения может сузить до None или открыть до Full — любой домен. Git-трафик идёт через кредо-прокси; эндпоинты выдачи токенов не форвардятся — добыть настоящий ключ изнутри нельзя.

Кредо-прокси: в среде суррогат GH_TOKEN, настоящими кредами прокси подменяет его только для репозитория этой сессии; push ограничен текущей рабочей веткой. Скоуп двухступенчатый: потолок — то, что видит подключённый GitHub-аккаунт, выбор при старте сессии — конкретное репо (установка GitHub App на репозитории нужна только для Auto-fix).

Порча — только текущая ветка push'а прикреплённого репозитория: даже уговорённый агент упрётся в прокси, а испорченный код виден на ревью PR. Утечка — содержимое репо и занесённые в сессию секреты по сети, в пределах её уровня доступа. Машина недосягаема.

Выводы-эвристики

Недоверенный контент — только за стенки

Письма, чужие PDF, веб-страницы приносят инъекции — скармливай их контурам со стенками: Chat, обоим Cowork, облачному Code. В локальный Code недоверенное не носят: там инъекция получает всю машину.

Секрет, попавший в среду, — скомпрометирован

Проектируй так, будто всё, что оказалось в песочнице, агент может слить. Так устроен кредо-прокси: настоящие ключи у брокера, в среде — суррогаты, привязанные к паре «сессия — репозиторий». Если ключ всё же нужен в среде — минимальный: fine-grained PAT на один репозиторий со сроком действия, а не gho_… со scope repo.

Автономность куплена containment'ом

Отпустить агента — длинные сессии, закрытый ноутбук, задачи по расписанию — можно только там, где ущерб заранее ограничен стенками. Локальный Code зеркален: полный доступ к машине в обмен на пошаговый контроль. Цепочка одна: сначала containment, потом автономность.
