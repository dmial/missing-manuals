Claude Desktop в компании: карта внедрения

Часть 1 · для внедренца: как устроить работу людей и агентов с общими знаниями
Черновик · вычитываем матрицу

Матрица внедрения

Внедрение Claude Desktop — это два независимых решения. Вертикаль — как способ работы распространяется между людьми: никак, добровольно или принудительно. Горизонталь — где живёт корпус знаний и какой доступ к нему получает агент: за API или в файлах. Найди свою клетку — она скажет, как устроена работа и какую цену ты платишь. Всё, что написано в заголовке строки или столбца, действует на каждую его клетку.

Корпус знаний → Носитель практики ↓ Знания за API Компания не меняет ничего: агент добавляется поверх привычных сервисов — но остаётся в них гостем. Ему поручают отдельные операции («найди», «создай», «допиши»), а не работу над корпусом целиком. Механика: SaaS-системы (Notion, Confluence, Drive, Linear) через коннекторы; доступ дозирован окошком запросов — нет grep, bulk-обхода и локальной среды; порог входа для людей нулевой; результаты падают в SaaS.
ChatВ полную силу: SaaS-поручения — родной жанр Chat. Корпус за коннекторами, окошка запросов достаточно; файловая среда не нужна. Скиллы плагинов работают и здесь — не доезжают только хуки и суб-агенты. CoworkС оговорками: коннекторы, плагины и автономные сессии работают полноценно, но главная сила Cowork — файловая среда — в SaaS-конфигурации простаивает. CodeС оговорками: удалённые коннекторы claude.ai Code подхватывает сам — локально при логине в аккаунт, в облачной сессии выбором при старте; свои MCP-серверы и плагины приходят его каналами — .mcp.json и CLI-маркетплейсы (enabledPlugins). Работает, но SaaS-поручения — не его профиль.
Знания в файлах Снимается потолок делегирования: корпус — рабочая среда агента, и поручать можно работу любого масштаба, вплоть до всего корпуса сразу («найди противоречия во всех договорах», «перелинкуй базу целиком»). Механика: агент читает и пишет файлы напрямую — grep, массовые операции, скрипты, связность как среда; нужен носитель у каждого (папка или клон); согласование копий — файл-синком или git (сравнение под матрицей); результаты ложатся на место в корпус. Просто локальную папку без синхронизации колонка не рассматривает: во всех её клетках корпус разделён — как минимум между твоими устройствами, дальше между людьми.
файл-синк ChatНе для этой конфигурации: файловой среды у Chat нет. К той же папке он дотянется разве что коннектором её сервиса (Drive и т. п.) — а это уже механика колонки «за API». CoworkВ полную силу: подключённая папка — родная стихия Cowork. Корпус — рабочая поверхность агента: grep, массовые операции, результаты ложатся на место. CodeС оговорками: синкованная папка для Code — обычная папка, работать можно (процедуры возьмёт из .claude/skills в ней же). Но без git нет истории смысла и отката корпуса целиком — у синка лишь версии отдельных файлов; облачным сессиям Code папка недоступна, а параллельные правки грозят синк-конфликтами.
git ChatНе для этой конфигурации: у Chat нет ни файловой среды, ни git — клон для него не существует. CoworkС оговорками: файлы клона — стихия Cowork, но сам git ограничен: локальной VM нужен токен (device flow или PAT), облачной сессии — только принесённый PAT, а git в подключённой папке через мост — офлайн, без pull/push. CodeВ полную силу: родная конфигурация Code — клон, ветки, ревью, петля «правка → дифф → коммит» (локально — на твоих ключах, в облаке репозиторий прикрепляется к сессии и push работает из коробки); .claude/skills приезжают с клоном — знания и процедуры одной поставкой.
1 · Солопрактика живёт в привычках одного человека — и уходит вместе с ним
Личный секретарь поверх сервисов

Сам подключил коннекторы в Settings → Connectors — и через минуты агент выполняет поручения в твоих сервисах. Самый быстрый старт во всей матрице. Работа агента не оставляет следа в общем корпусе — результаты растворяются по сервисам.
Личный корпус как рабочая среда
файл-синкЛичная папка (Drive, Dropbox) подключена к Cowork: архив одного человека становится поверхностью, по которой агент ходит свободно. Вклад синка — свобода перехода между устройствами (кросс-девайс): тот же корпус на каждом твоём компьютере, облачная копия заодно служит резервной. С телефона корпус тоже открывается — но лишь как файлы: агентской среды мобильные ОС не дают.
gitЛичный волт-репозиторий: та же кросс-девайс-свобода, плюс история и откат; петля «правка → дифф → коммит» в локальном Code.
2 · Команда (pull)практика живёт в договорённости равных: коллеги делятся, каждый подключает сам (pull); стандарт де-факто — держится на согласии и рассыпается с уходом людей
Общая приёмная

Командный плагин из внутреннего маркетплейса (git-репозиторий с каталогом; каждый добавляет его URL у себя сам) даёт всем одни процедуры поверх общих SaaS-пространств. Команда работает одинаково, но корпус агенту не принадлежит: процедуры общие — знания за окошком, и вклад агента в связность корпуса невозможен. Chat здесь в своей стихии — не доезжают до него только хуки и суб-агенты плагинов; Cowork всё умеет, но его файловая сила простаивает.
Общий корпус команды
файл-синкОбщая папка + плагин с процедурами (Code вместо плагина возьмёт их файлами — .claude/skills прямо в папке). Правка любого участника (и его агента) становится общей в момент сохранения — мгновенно, но без истории смысла.
gitВоркспейс-репозиторий: контент, CLAUDE.md и .claude/skills едут одним клоном — знания и процедуры в одной поставке. Правка становится общей через коммит и ревью; нетехническим — клон «под ключ», процедуры дублируются плагином. Imaga сегодня
3 · Организация (push)практика живёт в инфраструктуре: раздаётся админкой, закреплена политиками и аудитом (push); стандарт де-юре — не зависит от согласия и переживает смену людей
Агентизированный офис на существующем стеке

Сотрудник получает агента с подключениями «из коробки», не настроив ничего. Самая быстрая раскатка на масштабе и минимальная трансформация процессов — компания агентизируется, не меняя, где живут знания.
Корпус как институция
файл-синкКорпоративный Drive/SharePoint: зоны отделов, права режут видимость людям и их агентам одинаково, аудит средствами платформы.
gitDocs-as-code на организацию: плагин собирается из .claude/ репозитория и раздаётся сверху; максимальная агентность — корпус как среда, история как смысл — ценой инженерной поддержки как постоянной функции.
Cowork — режим в полную силу Code — работает с оговорками Chat — слабо / не для этой конфигурации

Внутри файлового столбца: файл-синк против git

Оба способа дают агенту одно и то же — корпус как файлы. Различие в режиме управления изменениями: как правка становится общей, что помнит система и кто что видит.

Файл-синк (Dropbox, Drive, OneDrive, Nextcloud)

+ Согласование непрерывное и автоматическое: сохранил — все увидели.

+ Права на подпапки из коробки: галочки в админке.

+ Нулевой порог входа: папка и есть интерфейс.

− Истории смысла нет: версии файлов вместо «что и зачем поменяли».

− Одновременные правки решаются «конфликтной копией», а не слиянием.

Git

+ Согласование транзакционное: правка становится общей коммитом, через дифф и ревью.

+ История как смысл: кто, что, зачем; откат любого состояния корпуса.

+ Знания и процедуры (.claude/) едут одной поставкой.

− Порог входа: нетехническим нужен клон «под ключ», git-рутину ведёт агент.

− Права на подпапки — только сабмодулями: отдельные репозитории со своими правами, с ритуалами инициализации и обновления. Работает, но заметно менее удобно, чем галочки файл-синка.
